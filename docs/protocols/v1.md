# 公開契約 v1

正本は `contracts/v1.json`。`python tools/generate_contracts.py` で Rust と TypeScript を生成します。
`--check` は生成漏れを検出します。未使用の表示契約も含みますが、実装済み機能は開発状況に記録します。
原記録・人格等の内部モデルは domain が所有し、スナップショットをスキーマへ照合するテストを置きます。
Snapshotのsourcesは古い記録から新しい記録への時系列順です。同時刻は保存順を保ち、クライアントで逆順に並べ直しません。

## HTTP と WebSocket

`/healthz` 以外は `Authorization: Bearer <端末トークン>` が必要です。TLS が既定です。
認証は端末単位、管理操作は admin 端末に限定します。公開専用端末は private データにアクセスできません。
v1 のメジャー互換性は明示し、未知のメジャーの拡張は起動前に拒否します。

| 経路 | 操作 |
|---|---|
| GET `/v1/snapshot` | 公開範囲に応じた状態。private 人格は public 応答から除去 |
| GET `/v1/capabilities` | ServerCapabilities。端末が利用できる文字・音声・表示・操作 |
| GET `/v1/modules` | 管理専用。モジュール定義・接続・開始順・状態・利用不能の理由。秘密情報なし |
| PUT `/v1/character` | PersonaUpdate。revision 必須 |
| GET `/v1/providers` | 設定された接続先と音声設定。秘密鍵自体は含めない |
| PUT `/v1/providers/active` | ProviderSwitch。変更前のチェックポイントを保存 |
| POST `/v1/chat` | ChatRequest → ChatAccepted。応答はイベントで増分配信 |
| POST `/v1/generations/{id}/cancel` | 音声・計算の中断要求。外部操作の撤回とは別 |
| POST `/v1/playback` | PlaybackAck。完了した文の1回限りの記録 |
| GET `/v1/events?session_id=...` | WebSocket。端末認証ヘッダー、公開範囲・セッションでフィルター |
| PUT `/v1/presence` | PresenceUpdate。60秒TTL、クライアントは15秒ごと更新 |
| GET `/v1/memories?history=true` | 記憶と版の履歴。履歴は管理端末のみ |
| POST `/v1/memories` | 本人の記憶の追加（MemoryCreate） |
| PUT / DELETE `/v1/memories/{id}` | 訂正・削除。revision 必須 |
| POST `/v1/memories/{id}/restore` | 同じ系統の版を本人が指定して復元 |
| POST `/v1/memories/review` | 原記録に基づく再評価案。自動適用しない |
| GET / PUT `/v1/grants` | 個別権限の閲覧・変更 |
| GET `/v1/extensions` | 起動した拡張のマニフェスト |
| POST `/v1/operations` | OperationRequest。一意ID、権限照合、実行台帳 |
| POST / GET `/v1/resources[/{id}]` | Content-Type付きバイナリの保存・取得。最大16MB |
| POST `/v1/resources/{id}/transcribe` | 明示した whisper.cpp へ音声認識を要求 |
| GET / DELETE `/v1/devices[/{id}]` | 端末一覧・失効。WebSocketも失効を確認 |
| POST `/v1/devices` | 管理専用。CreateDeviceRequest → CreateDeviceResponse。トークンは発行時だけ返し、保存はハッシュのみ |
| POST `/v1/backups` | サーバーデータ領域にSQLiteバックアップを作成 |

JSON の要求は未知のフィールドを拒否します。競合 revision / 重複操作 ID は409、権限不足は403です。
CreateDeviceRequestはname/audience/adminを明示します。通常アプリのadminはfalseとし、public管理端末は拒否します。
ConnectionBundleはschema_version=1、server_url、certificate_pem、device_id、app_id、tokenを持つファイル契約です。
証明書・端末トークンだけを渡し、所有者トークン・サーバー秘密鍵は含めません。64KiBまでを読み、対象アプリ・HTTPSを検査します。
tokenのwriteOnly指定に従い、生成Rust型のDebugはトークンを伏せます。ファイル自体は認証情報として保護します。
構成で無効または未接続の機能は認証・権限確認後、処理開始前に503
`{"code":"module_unavailable","error":"..."}` を返します。同時処理上限は503 module_busyです。
文字列はUTF-8バイト数で上限を持ちます。再接続時は snapshot を再取得します。
イベントの全件再送は行いません。ログ・会話の完全なオフライン同期は後続です。
イベントは `turn.started`, `text.delta`, `speech.segment`, `turn.completed`, `turn.cancelled`,
`turn.error`, `memory.updated`, `activity.recorded`, `character.provider_changed`。
`payload` の詳細は `runtime::Service::emit` の呼び出しに従います。型の細分化は次の契約更新で行います。

接続後、任意で次のClientHelloを送信します（EventEnvelopeで包みません）。

```json
{"kind":"client.hello","protocol_major":1,"session_id":"example-session","text":true,"audio_input":false,"audio_output":true,"presentation":true,"audio_mime_types":["audio/wav"]}
```

サーバーはkind=server.helloのEventEnvelopeを返し、payloadにServerCapabilitiesを入れます。
文字・音声の入出力・表示はサーバーの能力と端末の申告の共通部分に限定します。
session_idは接続クエリーと一致させ、途中の切替を拒否します。端末の認証・公開範囲・権限は変更しません。
未交渉の旧v1接続も維持します。新クライアントから旧サーバーへ接続した場合は、
capabilitiesの404をテキスト用の互換接続として扱い、未確認の音声は開始しません。

サーバーの構成型（CompositionConfig, ModuleDescriptor, CapabilityBinding, ModuleState等）も
contracts/v1.jsonから生成します。これは新しい第三者判断モジュールのRPC契約ではありません。

## 拡張

マニフェストにID、protocol_major、placement、実行コマンド、提供能力、要求権限、
JSON Schemaの入力型、フレーム上限、タイムアウトを宣言します。マニフェストはコードとして信頼する必要があります。
拡張はOSユーザー権限で動き、ファイル・環境変数への直接アクセスを本体で強制隔離しません。
本体経由の能力呼び出しは権限を検査しますが、未信頼拡張の直接操作を防ぐ機構ではありません。

UTF-8 NDJSON、標準入出力、一要求一応答、JSON-RPC 2.0。stdout は通信専用です。
初回 `initialize {protocol_major:1}` → `{protocol_major:1}`。
`invoke {capability,arguments}` → 型に沿う結果。終了は `shutdown {}`。
キャンセルは現行v1ホストではプロセス停止です。タイムアウト・切断後はオフラインとなり再起動を必要とします。
操作の結果不明状態から自動で同じ副作用を繰り返しません。
音声・画像は `MediaRef` の opaque resource ID で参照します。URIの任意取得を本体へ要求できません。

Python例は標準ライブラリのみで数値の姿勢データを返します。Rust SDKはフレーム制御とRPC型、
TypeScript SDKはディスパッチと上限付きstdio transportを提供します。Node.jsはサーバー・GUIに不要です。

## 接続仕様の参照先

Ollamaは `/api/chat` の増分応答と、設定した場合のみ `think` を使用します。
対応する値はモデルごとの仕様に従います。[Ollama公式API](https://docs.ollama.com/api/chat)

音声認識は multipart の `/inference` を使用し、合成は `/audio_query` → `/synthesis` です。
キャンセル可能合成はエンジン側の対応を確認した場合のみ有効にします。
[whisper.cpp公式server](https://github.com/ggml-org/whisper.cpp/tree/master/examples/server)、
[VOICEVOX ENGINE公式](https://github.com/VOICEVOX/voicevox_engine)
