# 構成と依存の方向

`desktop-gpui → client-core → HTTP / WebSocket → server → runtime → domain`。
`storage-sqlite` は `runtime::Repository` を実装します。`domain` は IO を行わず、
`runtime` は GPUI・SQLx・Axum・reqwest・標準モジュールの実装を参照しません。
`protocol` は公開スキーマから生成する通信型です。ドメインの保存モデルとの一致は契約テストで確認します。

一つの Cargo workspace 内の独立プロジェクトです。通常のサーバーは一実行ファイルで動作し、
SQLite はサーバーのローカルディスクに置きます。クライアントは状態の保存元になりません。
サーバーをクライアントの子プロセスとして起動する設計にはしていません。

## 状態と成長

原記録と記憶の版を分け、記憶には出典 ID・公開範囲・抽出モデル・処理版・期限を保存します。
AI の抽出は推測として保存し、本人の追加・訂正を確認済み情報とします。基本人格は本人の編集で変更します。
推測を読んだ回数やモデルの自己申告を信頼性の加点に使いません。
背景抽出は開始時の revision を使い、訂正・削除・モデル交換と競合した結果を拒否します。

訂正は新しい版と本人の新しい原記録を作り、古い根拠を以後の利用から抑制します。
削除は同じ記憶の系統と根拠を抑制し、抽出の再実行からの復活を防ぎます。
これは論理削除です。DBや過去のバックアップからの完全消去ではありません。
復元は同じ記憶系統の履歴から本人が明示的に行い、削除済みの系統は復元できません。

モデル交換は確認済み情報・人格・活動を変更せずチェックポイントを作ります。
再評価は原記録を添えた変更案の生成で、既存の記憶を自動置換しません。
検索は現在、期限・公開範囲・種別・件数で選ぶ方式です。ベクトル索引は未導入です。

## 会話と音声

会話は一つの実行核で調整します。モードは auto / quick / deliberate。
auto は軽量なルールで切り替え、別モデルによる毎回の事前判定を要求しません。
HTTP LLM の増分出力を短い文に分け、VOICEVOX の合成とクライアント再生を重ねます。
生成 ID・発話 ID・クライアントの再生世代で古いデータを破棄します。
クライアントが再生完了を通知した発話だけを会話済みの原記録にします。
再生完了は音声コールバックへの書き込み時点ではなく、ドライバーの予測再生時刻とバッファー長を待って判定します。
実機での停止遅延や機器切断の確認は採用ゲートに残します。
発話途中で中断した文の正確な既再生文字位置は未対応で、その文全体を未確認扱いにします。

録音はボタン操作による開始・終了で、最大30秒、16kHz mono WAV。
ハンズフリーの発話検出・エコー除去はまだありません。
モデルを閉じたことは外部操作の取り消しを意味しません。

## 自律活動と拡張

背景処理は会話がないときに記憶候補を抽出します。在席の有効期限は60秒です。
不在時の活動は次の会話候補を「予定」として記録します。架空の外部実行結果にはしません。
活動間隔・計画数・日次推論数を制限します。クラウドの無人推論は既定で無効です。
関係性の数値モデル、日課エディター、AI自身による長期目標の作成は後続実装です。

信頼して導入する拡張は標準入出力 JSON-RPC の別プロセスです。
権限は本体が実行直前に照合し、既定は拒否です。プロセス分離は OS サンドボックスではありません。
操作 ID は一意で、実行前に台帳へ保存します。クラッシュ後の Running は Unknown にし、再実行しません。
音声・画像は resource ID で渡し、JSON 制御メッセージに巨大なバイナリを埋め込みません。

## 上限と復旧

イベント512、クライアントコマンド32、音声キュー2、要求同時数8、拡張1プロセス1要求。
スナップショットは原記録100・記憶100・活動50件。全文履歴のページングは後続です。
音声等の一時リソースは1件16MB、合計128MB、1時間で期限切れ。
遅い WebSocket は切断し、再接続後にスナップショットを読み直します。
原記録・記憶は永続保存し、メモリへ全件を展開しません。ディスクの保持期間設定は後続です。

端末認証は失効可能な個別 Bearer トークン、DBにはハッシュのみ保存します。
HTTPS が既定で、自己署名証明書はクライアントへ明示的に配布します。
平文は明示した loopback 開発モードに限定します。
SQLx の移行履歴を確認し、未知の新しい移行を持つ DB は古い実行ファイルで開きません。
復旧は新規データディレクトリへのリストアで、既存 DB を上書きしません。

## サーバーの能力構成

サーバーの能力・接続を、独立した標準Rust crateと設定ファイルで組み替える。
`server::bootstrap → composition / modules → module-api → domain / protocol` が実装の依存方向。
`runtime → module-api / composition` で、特定の判断・HTTP/音声接続実装を参照しない。
クライアントは通常のアプリとして作り、画面・通信・音声・描画を内部で分割する。
共通APIを使うクライアントは標準接続を共有し、専用の変換が必要な接続先にサーバー側アダプターを追加する。
人格・記憶・権限は共通の実行核が所有し、GPUI型や画面レイアウトはクライアント内へ閉じる。
実行核は公開範囲で絞った情報を渡し、記憶の提案を出典・revisionで検査して確定する。
モジュールにはRepositoryを渡さず、自身の名前空間の固有状態だけをCASで保存する。
背景推論の予算と推論の同時数を共有する。保守は背景推論と独立したワーカーで動く。
接続と対話の無効化で管理・保存・保守は止まらない。未接続の能力は503を返す。
クライアントは能力を確認して入力・録音・発話要求を有効化し、helloは権限に使わない。
構成履歴とモジュール固有状態は人格のrevisionとは別に保存する。
