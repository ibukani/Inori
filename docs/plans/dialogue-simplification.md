# 第1段階の対話処理の簡素化

2026-11-07。ユーザー承認済みの実装単位。要件R22、判断は [ADR 0008](../adr/0008-minimal-dialogue-policy.md)。
[人格と会話の継続性](character-continuity.md)の第1段階だけを対象とする。

## 実装内容

- 人格と最小限の応答方針を渡し、質問・冗談・称賛・文数を縛る共通指示や能力不在の固定文を撤去する。
- 人格候補の禁止文を性格・価値観の表現へ整理する。保存済みの人格は変更しない。
- Autoの単語判定を撤去する。Auto/Deliberateはモデルの設定上限、Quickはモデル上限とquick_output_tokensの小さい方を使う。
- 記憶は本文・種別・出典・日時を分けて提示する。時刻・在席は取得できた情報だけを渡す。
- 現在入力・直近の往復・公開範囲・抑制状態・文字数上限を維持し、整形分も予算へ含める。
- 評価ツールで、出力上限差の明示的な許可・表示と、モデル観測と実装判定の分離を行う。

## 合格条件

実装の合格は入力・状態・権限・保存の検査に回帰がないこと。
モデルの不自然な返答や捏造は記録し、禁止文の追加、出力書き換え、追加LLMによる監視や再生成で隠さない。
モデルの発言を確認済み情報として保存する、削除内容が復活する、私的情報を公開入力へ渡す問題は不合格。
人物像の採否と実際の会話の確認はユーザーが行い、A/Bの点数から自動承認しない。

## 検証

修正直前の文脈・人格・ファイルハッシュを `.cache/dialogue-simplification-2026-11-07` に保存し、
同じ12場面を既存の同一モデル・設定で各3回生成する。旧比較データは保持する。
Autoの上限変更は比較画面と集計に明記し、同じ出力上限の比較と区別する。
入力・モデル設定の不一致、生成失敗、不完全な比較、文脈ハッシュ不一致は許可オプションでも拒否する。

モードと上限、参考情報のメタデータ、非取得とfalseの区別、整形後の予算を検査する。
既存の文脈・公開範囲・訂正削除・権限・音声再生確認の回帰検査と通常検査を実行する。
実際の結果は実装状況と専用の検証記録へ残す。実画面・実音声・24時間検証は追加しない。

機械処理のJSON契約、公開API、DB、GUI、モデル・推論設定、クラウド設定は変更しない。
関心の永続化と自発発話は対象外。
