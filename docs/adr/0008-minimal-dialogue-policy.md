# ADR 0008: 最小限の対話方針と実装・モデル評価の分離

状態: 採用・実装。日付: 2026-11-07。対象: R04/R10/R11/R21/R22。
ADR 0007の文脈保護は継続し、対話指示と品質判定の扱いを以下へ更新する。

## ユーザー確定事項

AIの性能差を受け入れ、将来のモデルで負債になる禁止プロンプトやモデル固有の補正は極力追加しない。
今回は第1段階の実装上の問題を直す。人格と実際の情報、最小限の応答方針を渡す。
Autoの深さは設定済みモデルの出力上限内でモデルに任せ、明示的なQuickの短い上限は維持する。

## 決定

共通対話指示から質問・称賛・冗談・文数の細かな制限と、入力に存在しない能力の固定説明を撤去する。
人格候補は性格・価値観・接し方を中心に整理する。保存済み人格を上書きしない。
Autoの「理由」「設計」などによる単語判定を撤去し、会話に応じた深さをモデルに任せる。
Quick/Deliberateの明示指定、プロファイルの資源上限、現在入力と直近の往復を優先する文脈保護を維持する。

記憶は参考情報として本文、種別、記憶ID、出典ID、作成日時、期限をJSONで分ける。
取得した時刻・在席情報だけを別の参考情報として渡す。非取得と在席falseは区別する。
文字数予算に整形後の全体を含め、収まらない参考情報を黙って断片化しない。

権限、記憶の確認済みへの昇格、訂正・削除抑止、公開範囲、操作ID、音声再生確認は既存コードで守る。
記憶抽出のJSONなど機械処理の契約は変更しない。追加のLLM判定、監視・再生成、出力書き換えは導入しない。

## 評価の扱い

実装は入力・状態・権限・保存の回帰検査で判定する。
モデルの一人称、自然さ、体験の捏造は別の観測結果とし、得点だけで実装合格やユーザー承認を決めない。
生成した話を確認済み情報として保存する、削除した情報が復活する、私的情報を公開入力へ渡す問題は実装上の不合格。

比較の入力・モデル設定の一致、完了標本数、文脈ハッシュを検査する。
Autoの変更による出力上限差は `--allow-output-limit-change` で明示的に許可し、画面・集計に差を記録する。
既定では従来通り出力上限の差も拒否する。旧レポート・採点の読み込みを維持する。
旧 `blocking_pairs` はモデル応答の問題として読み、実装の合否へ流用しない。

公開契約・DB形式・GUI・モデル・クラウド設定は変更しない。関心の永続化と自発発話は今回の対象外。
手順は [会話比較](../development/dialogue-review.md)、実装単位は [今回の作業](../plans/dialogue-simplification.md)。
