# 設計判断の一覧

ADRは判断の理由と当時の範囲を記録します。現在の実装・検証状況は
[実装状況](../development/status.md)、ユーザー確定事項は [要件表](../requirements.md) を参照してください。

| ADR | 判断と現在の扱い |
|---|---|
| [0001: Rust基盤と交換可能な周辺機能](0001-foundation.md) | 採用。Rustサーバー、SQLite、私有モノレポと公開拡張境界。GPUI方針は0004で補足 |
| [0002: モジュール構成管理](0002-module-composition-proposal.md) | 方針を採用。将来案も含む。初回実装の具体的な境界は0003 |
| [0003: サーバー構成の実装](0003-server-module-implementation.md) | 採用・実装。9つの標準モジュール、構成検証、実行核と保存の保護 |
| [0004: GPUIの継続](0004-gpui-resource-priority.md) | 選定方針はユーザー確定。本採用は対象環境の適合性検証待ち |
| [0005: チャット専用デスクトップ](0005-chat-client-management-boundary.md) | 採用。管理UIを別アプリへ分離し、独立音声トグル・VAD/AECをクライアントに配置 |
| [0006: 共通セットアップとOS常駐](0006-shared-setup.md) | 採用・初期実装。app-support、初回設定、接続ファイル、明示選択のサーバー常駐・配布 |

0005の「ログイン時の自動起動は今回実装しない」はその変更時点の範囲です。
0006で追加したOS起動時常駐はサーバーのサービスであり、デスクトップのログイン時自動起動は未実装です。
各ADRの未検証欄は判断時点の記録として読み、最新結果は実装状況と検証記録で確認します。
