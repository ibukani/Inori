# ADR 0002: 能力を組み合わせるモジュール構成管理

状態: 採用。既存機能の初回移行を実装し、具体的な境界は [ADR 0003](0003-server-module-implementation.md) で確定。
クライアントは通常のアプリとして作り、必要な接続の変換をサーバー側へ置く。
日付: 2026-11-06。
対象要件: R01, R02, R03, R04, R07, R08, R10, R12, R13。

## 背景

チャット・音声・自律判断・記憶整理・成長・行動・表示を、必要な組み合わせで利用したい。
改修前はLLMアダプターやJSON-RPC拡張を交換できる一方、対話や音声の調整はruntimeへまとまっていた。
本ADRは採用時の方針と将来の拡張候補を記録する。現時点の実装範囲と検証はADR 0003とstatus.mdを参照する。

カプコンの公式公開資料は、RE ENGINEがタイトルごとに異なる機能をモジュール化して互換性を維持する設計を説明している。
これをInoriの構成管理の着想とする。以下はInori向けの提案であり、RE ENGINE内部仕様についての記述ではない。
[カプコン公式・技術開発2022](https://www.capcom.co.jp/ir/data/oar/2022/development.html)

## 提案する境界

| 区分 | 責務 |
|---|---|
| 共通の実行核 | 状態の保存元、権限と公開範囲、出典・訂正・削除・revision、処理予算、操作台帳、処理の調停、生成ID・中断・再生確認 |
| 機能モジュール | 認識、注意、自律判断、計画、対話、記憶整理、関係性の適応、キャラクターの一時状態、行動、表現 |
| 接続アダプター | LLM、音声、機器、外部サービス、標準クライアント通信や専用サービスとの変換を提供する |
| クライアントアプリ | チャット表示・入力・音声機器・キャラクター表示を通常の部品分割で実装し、共通のデータ契約で接続する |
| 構成管理 | サーバー側の使用モジュールと能力の接続先を選び、起動前に構成を検証し、起動・停止を調整する |

判断方針は交換可能にする。判断を実行へ移す際の権限・予算・状態の整合性は実行核が検査する。
基本人格や確認済み記憶をモジュールごとに複製して別の保存元を作らない。
記憶・関係性モジュールは変更を提案し、本体が出典・revision・公開範囲・本人の確定情報を検査する。
標準の対話能力とチャットの接続機能も、サーバー構成から無効化できる設計を目指す。

## クライアントとの接続の見直し案

クライアントは、画面・通信・音声・描画を通常のRustの部品として整理する。
利用者がこれらを組み替えるためのモジュール登録器・依存解決器・プラグインローダーは初期版へ追加しない。
前の改修案に含めたchat.gpui・audio.native・renderer.basic2dというクライアント構成項目は取り下げる。

GPUI版や将来のWeb版など、共通HTTP/WebSocket契約を話せるアプリは同じ標準接続を利用する。
クライアントの製品名ごとにサーバー実装を分けない。
専用の通信形式、認証との連携、外部サービスとの入力・出力変換が必要な場合に、専用接続アダプターを追加する。
配信サービス等は将来の候補であり、今回の既存機能移行では新しい外部サービスを実装しない。

接続アダプターは入力を共通の要求へ変換し、応答・音声・表情等の出力を接続先へ届ける。
人格・記憶・判断方法をクライアントごとに所有しない。本人やセッションとの対応・公開範囲・権限は本体で検査する。
クライアントが申告した対応機能や接続アダプターの導入だけで、権限を増やさない。
サーバーは利用可能な能力を、クライアントは文字・音声・表示等の対応機能を共有し、適合する入出力を使う。
表示・再生ができるクライアントが不在でも、サーバーの状態と自律活動を維持する。

画面レイアウト・GPUI型はクライアントに閉じる。表情・視線・発話状態など意味のある表示要求を通信する。
モデル素材と将来の外部描画エンジンへの接続点はR12として維持する。
外部描画エンジンと全クライアント共通のモジュール構成基盤は別の責務として扱う。

## モジュール定義と接続

サーバーモジュールの定義にはID・版、提供する能力、必要な能力とその契約の版、実行方式、設定スキーマ、
要求権限、処理予算、状態のスキーマ版、起動・停止・異常時の扱いを持たせる。

依存先は実装名ではなく能力の契約で表す。例えば対話は「推論する能力」を必要とし、
Ollama固有の型には依存しない。構成側でその能力へ利用する実装を明示的に割り当てる。
複数の提供元がある場合の選択・用途別ルーティングも構成に明示し、自動でクラウドへ切り替えない。
依存解決によって権限や私的情報の送信許可を自動付与しない。

起動前に不足した依存、循環依存、非対応の契約版、競合する排他実装、配置先の不一致、
設定の不備を検出する。権限不足は理由を表示し、該当の呼び出しを拒否する。
実行中も権限・予算・状態の検査を継続する。

モジュール間の要求・イベントには型と公開範囲を持たせ、依存する相手と用途を明示する。
イベントの自己再処理からの循環には、因果関係のID・処理回数・キュー上限を設ける。
公開契約は既存のcontractsから生成する方式を引き継ぐ。
サーバー拡張へGPUI型やSQLiteへの直接アクセスを要求しない。

## 構成の例

以下は将来の能力も含む組み合わせの例。実装済み部分の設定例は configs/examples の
minimal.toml / autonomous.toml / companion.toml に置く。

| 構成 | 組み合わせ |
|---|---|
| 小さな自律キャラクター | 時刻・在席、軽い自律判断、記憶整理、一時状態。接続するアプリが簡易2D等で表示する |
| 音声で話せる相棒 | 上記と対話、音声認識、音声合成、音声対応の接続。マイク・再生はアプリが担当する |
| 作業支援 | 対話、状況判断、作業スキル、通知、本人が許可した操作 |
| 将来の配信 | 公開セッション用の入力・対話・音声・表示と、公開範囲を検査する本体 |

同じキャラクターの状態を維持して能力を組み替える。私的・公開セッションの情報の境界は引き継ぐ。
構成の変更履歴を保存し、無効化だけで記憶やモジュール固有の永続状態を削除しない。
モジュール固有の状態も、本体の管理下で名前空間とスキーマ版を付けて保存する。
状態形式の変更はバックアップ・移行・復旧の検証対象とする。

## 実行方式と初期の範囲

標準のRustモジュールは独立したcrateに分け、初期は主に同じサーバープロセス内で呼び出す。
クライアントは既存のclient-coreとGPUIアプリの分離を活かし、通常のアプリとして保守する。
第三者製・他言語・独立した更新や障害分離が必要な拡張は、既存の別プロセスホストを利用する。
同一プロセスのRustインターフェイスと公開JSON-RPCの契約には変換層を用意する。
Rustのdylib ABIを第三者向け公開境界にはしない。
同一プロセスの標準モジュールの更新には、初期はアプリの再ビルド・再起動が必要である。

サーバーの起動構成と設定ファイル、依存検証、状態保持を整える。
初回は既存の標準機能をまとめて移行し、組み替えは設定ファイルと再起動で行う。
第三者製の新しい判断モジュールSDKは次段階とし、既存のLLM接続・JSON-RPC拡張は引き継ぐ。
実行中の無停止差し替えやGUIの構成グラフエディターは、その後の検討とする。
同じ重みのモデルを各モジュールが個別に読み込むことを必須にせず、接続先と予算を共有できるようにする。
モジュールごとに常時LLMを呼ぶ構造にせず、必要な出来事や時刻で処理を起動する。

## 段階的な移行案

1. 既存の保護処理と受け入れテストを維持し、モジュール定義と構成検証器を追加する。
2. 対話、記憶整理、自律判断、認識、音声、推論、操作と標準クライアント接続の既存サーバー処理を標準モジュールへ切り出す。
3. クライアントはサーバーの利用可能な機能を参照し、表示と操作を制御する。クライアント側の構成管理基盤は作らない。
4. 対話や接続を無効にしても状態・管理・自律活動が継続し、同じ能力の別実装へ交換できることを検証する。
5. 後続で第三者製の判断モジュール用SDKと、必要な専用接続アダプターを追加する。

既存のRust/GPUI、保存、認証、公開契約、SDK、テストを移行の土台として使う。
全面的な作り直しを前提にしない。実装時には、依存方向・契約・CIと実装状況を一緒に更新する。

## 改修の受け入れ条件

- チャットなしの構成でも、キャラクターの保存と自律活動が動く。
- 依存の不足・循環・非対応版・実装競合を起動前に検出できる。
- 同じ能力の実装だけを交換しても、人格・確認済み記憶・活動状態が保たれる。
- 無効化と再有効化で状態が意図せず消失せず、古い処理結果が復帰後の状態を上書きしない。
- 接続先の選択と権限付与を区別し、私的情報の送信・副作用の検査を迂回できない。
- 模擬時刻・模擬AI・記録した架空のイベントから、構成ごとの挙動を検証できる。
- モジュール数が増えた際のRAM・CPU・待ち行列・会話遅延を測定し、構成ごとの予算を確認できる。
- 共通契約を話す別のクライアントでも、製品ごとの専用モジュールを必須にせず同じ人格・記憶を利用できる。
- 接続アダプターが私的情報の参照・操作権限・本人との対応を迂回できない。
