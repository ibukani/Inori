# ADR 0009: 宅内LAN自動接続とインターネット公開

日付: 2026-11-07。状態: 採用（ユーザー確認済み）。

## 確定要件

ユーザー確定事項（R06/R23）: 同じ家のPCはデスクトップアプリから簡単に接続できる。必要に応じて自宅サーバーへ一般のインターネットから接続する。外部接続は簡単にON/OFFし、OFF中も宅内接続を保つ。

## 決定

- インターネット経路は直接公開を先に実装する。安定した公開URL/DDNSが必要。LAN TCP 9473と分離するため、公開URLはTCP 9474を使い、IPv4ルーターでは外部TCP 9474からサーバーTCP 9474へ転送する。IPv6待受もTCP 9474を使う。
- LAN待受はTCP 9473を維持し、LAN検出にはUDP 9475のnonce付き問い合わせを使う。応答は公開情報と証明書指紋だけを含み、端末認証情報は含めない。クライアントはペア済み証明書の指紋が一致した応答だけを候補とし、接続時もURLのホスト名をTLS検証に使う。
- 公開待受は初期状態で閉じる。所有者認証付きのサーバーCLIが宅内待受を通じてモードを変更し、公開待受だけを開閉する。ネットワーク管理APIは公開用ルーターから除外する。
- 新しい接続用ファイルはv2で、直接URLとLAN自動検出経路を含む。既存v1接続ファイルも取り込める。端末トークンはTLS確認後にだけ送る。
- 現行の証明書ピン留め方式を使い、ブラウザー向けCA証明書や中継事業者を必須にしない。証明書名の追加で再発行する場合は既存ペアリングを再取り込みし、旧鍵・証明書は `.previous` として保持する。
- 中継経路は後から追加できる契約上の種別だけを設ける。中継サーバー・事業者・アカウント・料金は今回選定しない。

## 影響と未検証事項

- DNS/DDNS、ルーター転送、ホストファイアウォールはセットアップ文書で案内する。これらは自動変更しない。
- 新デスクトップはLAN検出により `home-server` の名前解決へ依存しない。旧デスクトップは自動検出に対応しない。
- IPv4ブロードキャストによるLAN検出はルーターで遮断される場合がある。実際の宅内ルーター、別PC、CGNAT、IPv6のみのLAN、証明書再取り込みの実機検証は未実施。
- 直接接続不能な回線で中継を使うには、別途中継方式の実装・選定が必要。
