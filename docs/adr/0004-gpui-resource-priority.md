# ADR 0004: 低負荷・省メモリを重視したGPUIの継続

日付: 2026-11-06。
状態: 選定方針はユーザー確定。実機適合性の合格・本採用は検証待ち。
ADR 0001のクライアント選定理由を補足する。サーバーの境界・公開契約は変更しない。

## ユーザー確定事項

アプリ実行時の負荷・メモリ使用量をできるだけ抑えたいという理由から、
WindowsクライアントにはGPUIを使用する（R17）。対象は引き続きWindows、RAM8GB、専用GPUなし（R06）。
継続開発・信頼性の要件（R13）も維持する。

## 設計判断

既存のRust + GPUIクライアントで継続開発し、Tauriへの移行・比較試作は現行計画に含めない。
GPUIの選定方針と、対象機器で要求を満たしたという検証結果を分ける。
[GPUI採用ゲート](../development/gpui-gate.md)を満たすまで適合性検証用の試作として扱う。

人格・記憶・自律活動は独立サーバーが所有する。
GPUI依存はdesktop-gpuiに閉じ、client-coreと公開契約を維持する。
サーバー・runtime・storageへGPUIやクライアント音声の依存を持ち込まない。

今後の最適化は次を方針とする。これらの実装・効果は本ADRで確認済みとはしない。

- 状態変化に応じた画面更新を基本に、不要な再描画・ポーリングを抑える。
- 最小化・非表示時の不要な描画・アニメーションを止め、必要な接続・状態同期・音声処理を維持する。
- 履歴の遅延表示とキャッシュの保持量を見直し、履歴全件の常時メモリ展開を避ける。

## 仮目標

T03のクライアント300MB・実行核200MBを維持する。新たなCPU・GPUの数値目標は確定しない。
AI・音声エンジン・外部renderer等は別途総量を報告する。
表示・待機・最小化・音声動作時を分けて測定し、常駐時の不要な処理と保持メモリを減らす。

## 仮定と未検証事項

GPUIの継続は低負荷・省メモリを目指すための選択であり、Tauri等より必ず低負荷であるという前提は置かない。
他UI方式との比較、対象8GB・内蔵GPUでの適合性、IME変換、スリープ復帰、透過・ウィンドウ制御、
実音声、24時間のGUI常駐は未検証事項として残す。

既存の短時間の測定は [過去の性能測定記録](../development/performance-history.md) に記載した条件に限る。
今回の変更は文書のみで、最適化の実装や性能の再測定を行ったという主張は含まない。
以後の結果にもハードウェア、ビルドプロファイル、エンジン稼働状態、サンプル時間を併記する。
対象機器でreleaseビルドを測定し、CPU、Working Set、Private Bytes、GPU使用量を記録する。

## 重大な問題が残った場合

まずGPUI内での修正・最適化を検討する。採用ゲートに重大な未解決問題が残る間は、広いUIの作り込みを止める。
選定方針の変更が必要になった場合は、測定結果と制約を根拠に別ADRで提案する。
