# ADR 0007: 人格と会話の継続性を段階的に検証する

状態: 採用。第1段階の対話処理を実装。人物像と品質の合格は確認待ち。
日付: 2026-11-07。対象: R01/R04/R10/R11/R21。

更新注記: 以下は初期実装時の判断。[ADR 0008](0008-minimal-dialogue-policy.md)で対話指示を最小限に整理し、
実装の合否とモデルの会話品質の観測を分離した。文脈・情報保護の判断は継続する。

## 決定

人格が伝わる一回の会話、関心を保存して次へつなぐ会話、自発発話の順に一段階ずつ完成させる。
各段階に同条件の実AI比較とユーザーによる会話確認を置く。
参考作品・人格候補を示さず、AIが作った正解台詞だけで品質を判定しない。

人物固有の性格は既存personaの入力として渡し、標準対話モジュールにInori専用の性格を埋め込まない。
新たなLLM分類呼び出しは追加しない。共通の会話方針で、相手の今の発言に合う反応・意見・質問を促す。
人格候補は別ファイルとし、既存DB、保存済み人格、モデル、クラウド設定へ自動適用しない。

内部DialogueInputへ現在のユーザー原記録IDを追加する。
本文の一致だけで履歴から現在入力を取り除くと、同じ発言を繰り返した場合に過去の発言と区別できないため。
現在入力と必須の人格・方針を先に予約し、直近から往復単位で履歴を取り、その後に追加の記憶・時刻を入れる。
文字数は全方針文を含めUnicode文字数で計算し、必須部分が入らなければ失敗を返す。
入力・基本人格を黙って切り詰めない。履歴先頭が応答途中の場合は孤立した応答を入れない。
公開範囲・抑制済み原記録・記憶状態も対話層で確認するが、元の選別・権限検査は実行核に残す。

## 互換性と検証

今回の変更は内部型と対話方針。公開契約、DB形式、API、GUI、音声再生確認は変更しない。
内部Rust traitは安定した第三者ABIではなく、workspace内の実装をまとめて更新する。
将来の関心管理・availability・ターン開始理由は、各段階へ進んでから公開スキーマを正本として追加する。

評価用exampleは本番と同じ対話方針・推論アダプターを使い、DBを開かずに固定した架空入力を評価する。
改修前の入力文脈を保存し、モデルと設定が同じ場合だけ比較画面を作る。
対話検査、workspace回帰検査、実AIの生成成功、主観的な品質合格を別々に記録する。
詳細は [段階実装](../plans/character-continuity.md)、[検証手順](../development/dialogue-review.md)。
