# Windows GUIとセットアップの検証（2026-11-07）

## 条件

Windows 11 Home build 26200、Ryzen 7 5700X、RAM 34,284,941,312 bytes（約32 GiB）、
RTX 4070 SUPER。`cargo build --locked --offline --release -p inori-desktop` のWindows x64版を使用した。
Computer Useで実ウィンドウを操作し、画面表示と、保存ファイル・独立プロセスの状態を照合した。
通常サイズと最大化で確認した短時間の機能検査であり、性能・24時間運用の測定ではない。

保存先はGit対象外の `.cache/gui-verification`。専用ポートのHTTPSサーバーと架空の端末・会話だけを使用した。
組み込みmock、外部推論なし、自律活動OFF、背景推論予算0。実クラウド、録音、音声再生、実エンジンは使っていない。
音声OFFの確認時だけ、ループバックのダミー接続先を設定してSTT/TTS能力を通知させた。
この確認は音声エンジンへの接続成功を意味しない。実ユーザーの設定とOSサービスは変更していない。

検証したrelease実行ファイルのSHA256:

- desktop: `70c4bf35d830cc8f9504c4ff80c1d1a134e6734e22752088966c1ec468b7dccb`
- server: `ac5a2dfe4e77aa13f893bf0fad8623370cc91f88aef8eccd77677f502f4ed6b9`

## 実画面の結果

| 操作・条件 | 結果 |
|---|---|
| 認証ファイルがない設定から起動 | 接続設定画面を表示した |
| ネイティブファイル選択・接続ファイル取り込み | 接続先URL・証明書の指紋・端末IDを表示。トークンの値は表示しない |
| 取り込みをキャンセル | 保存設定は元のまま、認証情報用ディレクトリを作らないことを照合した |
| 接続して保存 | TLS・通常端末の認証・機能確認に成功。アプリ専用の接続領域へ証明書とトークンをコピーした |
| 保存後にクライアントを再起動 | 同じ接続設定を再利用し、履歴を表示した |
| 日本語Unicodeの入力・Enter送信・mock応答 | 入力と応答を表示。修正後は利用者→AIの順を維持した。IME変換操作は実施していない |
| 存在しない認証ファイルで接続して保存 | ファイルを読めない理由と取り込みの案内を表示。保存済み設定のバイト列は変わらない |
| サーバーの停止・同じデータで再起動 | 接続待ちと設定画面へ移り、自動再接続後も履歴を保持した |
| 通常表示・最大化・通常表示へ復帰 | チャット・入力欄・音声操作を表示した |
| ウィンドウの閉じる操作 | プロセスを終了せず最小化し、再度アクティブ化して復帰した |
| Ctrl+Q | クライアントが終了した。その後もサーバーのHTTPS healthが成功した |
| 音声能力なし | マイク・AI音声は「利用不可」だった |
| ダミー音声能力ありで新規起動 | マイクOFF・AI音声OFFを表示。どちらもONにしていない |

検証後はクライアントの通常終了を確認し、自分で起動した検証用サーバーも停止した。

## 見つかった不具合と修正

1. 接続失敗時のメッセージがチャット画面にしか描画されず、設定画面で理由が見えなかった。
   接続設定にも状態・失敗理由を表示する領域を追加し、認証ファイル不在で再検証した。
2. Snapshotの履歴は時系列順なのに、GUIが逆順に並べていた。
   APIの順序をそのまま表示するよう修正した。サーバーの実チャットテストでもSnapshotの利用者→AI順を検査する。
