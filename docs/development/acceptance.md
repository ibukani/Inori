# 受け入れ条件と証拠

完全な製品の合格表ではありません。自動検査と実機のゲートを分離します。
現在の概要は [実装状況](status.md)、優先順と完了条件は [次に行うこと](../plans/next-steps.md) に記載します。
実画面・実AI・性能の証拠は既存の検証記録を参照します。今回の整理では実機確認・性能再測定を行っていません。

| 条件 | 証拠 | 残る検証 |
|---|---|---|
| モデル交換後も人格・確認済み情報・活動を保つ | storageの交換テスト、APIの記憶ライフサイクル、Python推論への交換、Ollama実接続 | 長期活動・モデル性能差の品質評価 |
| 古い背景処理が訂正を上書きしない | domainのStaleRevision、storageの訂正トランザクション | 長時間の並行負荷 |
| 訂正・削除内容が再要約や検索から復活しない | 根拠のsuppression、再起動テスト、抽出receiptの保持 | ベクトル検索は未導入 |
| 古い音声と未再生部分を会話済みにしない | 再生世代のテスト、音声HTTP統合、取消・重複ackテスト | ドライバー遅延・物理出力・中断途中の文字位置 |
| 結果不明の副作用を再実行しない | Unknown復旧・重複ID・権限テスト、実HTTPSでの拡張呼出し | 実際の家電操作は対象外 |
| 私的記憶が公開入力へ混入しない | API公開範囲、CaptureProviderによる実入力検査 | 配信クライアントは後続 |
| 拡張が実行核の内部を参照しない | Python標準ライブラリだけの数値入力・推論例、Rust/TS SDK | 外部音声・描画ホスト |
| キューやメモリが際限なく増えない | 各上限、巨大フレーム拒否、タイムアウト停止、限定スナップショット | 高負荷の総メモリ・24時間測定 |
| Windows/macOS/Linuxサーバービルド、GUI分離 | Windowsビルド、check_boundariesとcargo tree、各OSのCI定義 | macOS/Linuxのビルド・起動、各OSのCI実行結果 |
| GPUIで低負荷・省メモリのWindowsクライアントを開発する（R17） | 既存GPUI試作、選定方針のADR 0004、[旧構成の短時間測定](performance-history.md) | 対象8GB・内蔵GPUでのrelease測定、待機・最小化・音声動作時の負荷、T03、24時間常駐 |
| デスクトップを画像なしのチャット専用画面にする（R18） | 単一時系列画面、接続設定、管理画面の除外、ADR 0005。[Windows releaseの実操作](gui-validation-2026-11-07.md)で表示・mock会話・設定再利用・再接続を確認 | IME変換・候補位置、最小サイズ、対象8GB・内蔵GPUでの操作 |
| 独立したマイク・AI音声トグルとトレイ音声会話（R19） | client-coreのVAD/AEC経路、合成音声検査、発話区切りテスト、トレイメニュー実装 | トレイの実画面操作、実マイク・スピーカー・VOICEVOX、エコー除去、T02の150ms測定 |
| 対話なしで認識・記憶整理・自律活動、全能力なしで管理・保守 | composition統合テスト、共有予算消費後の期限切れリソース整理 | 長期の負荷 |
| 無効な機能が処理を始めず、クライアントも音声入力等を開始しない | APIの503・無記録、client-coreの開始抑止、設定例の静的検証。[実画面](gui-validation-2026-11-07.md)で音声能力なしの「利用不可」とダミー能力ありの起動時OFFを確認 | 実音声中の能力喪失・機器切断、無効構成全般の実画面操作 |
| 構成変更・無効化・再有効化・再起動で状態を保つ | composition履歴とmodule状態CAS、保存・再起動テスト | 将来の固有状態の移行 |
| 同じ能力へ別の実装を接続する | 試験用dialogue.alternateを同じAPIから呼ぶ統合テスト | 第三者判断SDKは後続 |
| クライアントの申告が権限やセッションを迂回しない | 実WebSocketでhello・旧接続・公開範囲・セッション不一致の拒否 | 専用サービス接続は後続 |
| 共通上限・中断・モジュール故障の処理 | 共有推論の上限、待機中の中断、別端末の中断拒否、準備失敗の逆順終了、拡張タイムアウト | 長時間の複合障害 |
| 旧DBのコピー後だけ追加移行する | ロック競合・旧形式の単独backup・pre-schemaコピーの版を検証 | 運用環境での復旧訓練 |
| 共通セットアップ・接続ファイル・展開型配布・選択式サーバー常駐（R20） | app-support、setup/doctor/export-connection/service、アプリ宣言、配布ツール。[Windows検証記録](gui-validation-2026-11-07.md)で設定・TLS認証・通常端末・ZIP照合・展開後起動を確認 | Mac/Linuxの実ビルド・導入、OSサービスの実登録・OS再起動・ログイン前稼働、開発ツールなしのクリーンOS |

R01〜R20の要件IDは [要件表](../requirements.md) が正本です。関連する実装は
`domain`（R04/R07/R11）、`runtime`（R01/R03/R05/R09/R10/R11）、
`protocol`/SDK（R02/R08/R12）、`client-core`/GPUI（R06/R09/R10/R12/R17）、
workspace/CI/ADR（R13）、単一チャット画面（R18）、クライアント音声制御（R19）へ分けています。
module-api / composition / modulesとサーバーの起動元がR14〜R16を担当します。
app-support・server setup/service・アプリ宣言・開発配布ツールがR20を担当します。

テストの実体は [検証の配置](../../tests/README.md)、コマンドは [quickstart](quickstart.md#通常の検査)、
UIの本採用条件は [GPUI採用ゲート](gpui-gate.md) を参照してください。
